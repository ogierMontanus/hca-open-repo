# V0.92 structural diff

The `HCA-Repository V0.82.xlsx` master that has fed this project so far was a
single workbook. The new drop in `data/raw/HCA REPOSITORY V0.92/` is **nine
workbooks** organised by domain and by processing stage. The change is not a
content patch — it is a structural reorganisation that puts the source on a
star-schema footing.

Authoritative structure description lives in the project PowerPoint *Møde den
16. Juni.pptx* (slides 11–24). This note captures what is visible from the
sheet headers and the file naming convention so coding agents can plan against
it.

## File typology

Three filename suffixes encode the processing stage of each workbook:

| Suffix | Stage | Purpose |
|---|---|---|
| `-PQ-V0.92.xlsx` | **Power Query** | Semi-raw, domain-scoped extracts. The "Data" files. |
| `DiaryFactDim-PQ` | **Fact + Dimension extract** | Diary-centric. Pulls dimensions and facts that connect diary pages to Persons, Calendar and Locations. |
| `-PP-V0.92.xlsx` | **Power Pivot StarSchema** | Dimensions and Facts already loaded into a Power Pivot data model. Pivot tables are generated from these. |

## Contents of V0.92

## V0.82 → V0.92 — what actually changed

| Aspect | V0.82 | V0.92 |
|---|---|---|
| File layout | **One** workbook (33.9 MB) | **Nine** workbooks (52 MB) split by domain × stage |
| Schema shape | Flat register sheet (`Registry`) lumped works + persons + places | **Star schema:** explicit `Dim*` (dimensions) + `Fact*` (relations) tables |
| Per-page granularity | Implicit (had to be derived from `RefInDiaryPage`) | First-class — `DimDiaPag`, `DimPerPag`, `DimLocPag` are their own tables |
| Cross-references | Inline `, se: …` inside `RegistryTitle` (461 unparsed for persons/places, see source-field-audit.md) | Explicit `Raw.See-Also` table in `LocationData-PQ` |
| Calendar | `Calendar1800` sheet | `CalendarData-PQ` with `DimCal` + `DataCal` — 14 columns vs. previous narrower set |
| Works register | Present (3,708 works) | **Absent** — V0.92 does not yet ship works data |
| Diary coverage | All 12 volumes (2,177 pages) | Vol VI–VII subset (still 2,177 pages — overlap not confirmed without opening sheets, but likely the same total surfacing the same pages with Vol VI/VII *fully* dimensionalised and the rest as carry-over) |
| Pivot readiness | Required external Power Query | Ready Power Pivot data model in `-PP-` files |

The biggest qualitative shifts:

1. **Star-schema formalisation.** V0.92 brings the warehouse design that
   `docs/data-model/star-schema.md` proposed. Dim and Fact tables are now
   real artefacts, not a future target. The MVP path in §2 of that doc no
   longer needs to *build* the star — it just needs to *load* it.
2. **Co-occurrence is shipped.** `FactDiaLocPerPag` (92,307 rows) is the
   authoritative co-occurrence grain. The mockup's `cooccurrence.js` becomes
   a fallback for the V0.82-era CSVs.
3. **Cross-references move out of the title string.** `Raw.See-Also` makes
   the parser pass tracked in §15.1 of `coding_agent_plan.md` partially
   obsolete — for places, at least, the relation is now structured. The
   §15.1 attention point should be re-scoped to *persons* once V0.92 grows
   a person-side equivalent.
4. **Works are missing from V0.92.** The mockup's three wing landing pages
   continue to depend on V0.82 until a `WorkData-PQ-V…xlsx` (or similar)
   ships. Coexistence rather than cutover is the right transition stance.

## Implications for the pipeline

1. `scripts/normalization/hca_xlsx_to_csv.py` is single-file V0.82-shaped.
   A new `hca_v092_to_csv.py` (or a `--source` flag) is needed to load
   the nine V0.92 workbooks and emit the same three normalised CSVs
   (`entities.csv`, `diary.csv`, `references.csv`) — at least for the
   Persons / Places / Diary slice that V0.92 covers.
2. Until V0.92 ships works, the normaliser **must remain dual-source:**
   reads persons + places + diaries from V0.92 where available, works from
   V0.82. Document this clearly in the script header.
3. The new `FactDiaLocPerPag` co-occurrence table can replace the
   `scripts/build_mockup/build_cooccurrence.py` output once persons/places
   are sourced from V0.92.
4. `Raw.See-Also` in `LocationData-PQ` should populate `entities.see` for
   the 76 place entries that V0.82 left unparsed (per
   `source-field-audit.md`).
